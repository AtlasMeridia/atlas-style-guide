01 / 07

The font story contradicts itself

A

Four faces are wired; the docs describe three

Fix now

The stylesheet and the lint config — the two enforced sources — load and allow four families and set --font-body: 'Literata' as the reading face. But the README, SKILL, and even the fonts table all still say "Fraunces is display and body" and barely mention Literata. The Literata decision only lives in a leftover scratch file. An agent following the prose will set body text in the wrong face every time.

  • colors_and_type.css — @import loads Fraunces · Literata · JetBrains Mono · Noto Serif TC; --font-body = Literata
  • _adherence.oxlintrc.json — allow-list is the same four (including Literata)
  • README.md / SKILL.md — "Fraunces is the face — display and body"; Literata never named
  • fonts/README.md — says "three families," omits a Literata row, yet its token note lists --font-body (Literata)
Recommend

Keep Literata — it is the deliberate reading-face pick (you A/B'd five serifs and wired it + linted it). Update all three docs to state the truth: four fonts — Fraunces for display only, Literata for body, JetBrains Mono for UI/mono, Noto Serif TC for CJK. State the body face once. (If you'd rather run three, drop Literata from the CSS and lint and revert body to low-opsz Fraunces — but that discards the test you already ran.)

02 / 07

One system, three names

B

"Minerali," "ATLAS Meridia," and "Remix" all mean the system

Decide

The README rebrands the system to Minerali and says "Remix" is now just the house style — retire the label. But the project title, the manifest namespace, two root filenames, and every Brand card still carry "ATLAS Meridia" and/or "Remix." Products (ATLAS / Meridia, Hermes, Aeon) correctly keep their names; the system name is what's unsettled.

  • namespace — ATLASMeridiaDesignSystemRemix_23cc54
  • root files — "ATLAS Meridia - Remix Design System.html", "ATLAS Hermes - Remix Chrome.html"
  • cards — "Remix — Hero", "Remix — Voice", "Remix — Palette" … (×7)
  • tokens — every custom property is prefixed --rmx- (Remix)
  • domain — README says kennyliu.io; SKILL & project say kennyliu.io
Recommend

Lock Minerali as the system name; keep ATLAS / Hermes / Aeon as products; retire "Remix" as a label in filenames, card names, namespace, and docs. Leave the --rmx- token prefix as-is — renaming it touches every token in every file for zero user-visible gain; treat it as a legacy prefix, or schedule a mechanical rename later. Fix the domain to kennyliu.io everywhere.

04 / 07

The token model has a theming trap

D

The SKILL points authors at tokens that break theming

Fix now

There are two token layers: raw brand tokens (--rmx-paper, theme-independent) and semantic tokens (--text-primary, per-theme). That's fine — but SKILL rule #3 tells authors to set text with --rmx-paper / --rmx-bone. Those don't flip in the cream theme, so any surface built that way silently fails daylight mode. The skill is steering people toward the bug.

  • SKILL.md rule #3 — "Build on ink/graphite with --rmx-paper / --rmx-bone text"
  • aliases — --font-ui ≡ --font-mono (identical); --success ≡ --accent-cut; --warning ≡ --accent
Recommend

Set one rule and put it in the README: raw --rmx-* only for brand-fixed marks (the logo, the acid cut); semantic --text-* / --bg-* / --border-* for everything that must theme. Fix SKILL rule #3 to use --text-primary / --text-secondary. Either collapse the duplicate alias tokens or label them as intentional — don't leave them ambiguous.

05 / 07

The brand shelf is overstocked

E

Eight brand cards, with three heroes and a redundant index

Consolidate

Of 25 cards, 8 are Brand. Three of them — Hero, Manifesto, Specimen — are the same editorial hero composition shown three ways. And "Remix — Index" is a 1440×2200 contact sheet that re-renders the other specimens, when the Design System tab grid is already the index. Every extra specimen is one more thing to keep on-palette as the system evolves.

  • overlap — remix-hero · remix-manifesto · remix-specimen all read as one composition
  • Remix — Index — 2,200px tall; duplicates content the card grid already shows
Recommend

Drop "Remix — Index." Keep one hero (the strongest of the three), plus wordmark, monogram, voice, and icons — Brand goes from 8 to ~5. Fewer, sharper specimens; less surface to keep in sync.

06 / 07

Two nocturnal themes that nearly overlap

F

Graphite and dark differ mostly in ground depth

Decide

Three themes ship: graphite (#1a1a1d, default), dark (#07080a), and cream (daylight). Graphite and dark are both nocturnal ink grounds; the practical difference is ground lightness and a one-step body weight (340 vs 330). Cream is the real outlier. Three themes is three sets of tokens to maintain and test.

  • graphite bg #1a1a1d · weight 340  —  dark bg #07080a · weight 330
Recommend

A judgment call — keep all three only if terminal / Hermes surfaces genuinely need the deepest ink. Otherwise keep graphite + cream and make the deepest ink a one-off override rather than a third maintained theme. Your call; there may be product reasons I can't see.

07 / 07

The same rules, written three times

G

README, SKILL, and fonts/README restate each other

Consolidate

Voice, color, type, and motion rules are spelled out in full across three documents. Restating values in three places is exactly how they drift — finding A is the proof that it already happened. The fix isn't more editing discipline; it's not duplicating the content.

Recommend

Make README the single source of truth. Cut SKILL down to a short operator's note — "read the README, here's how to apply it." Reduce fonts/README to the load table only. State each value once, link to it from the rest.
